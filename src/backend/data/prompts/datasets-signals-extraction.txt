You are an expert academic researcher specializing in metascience and dataset sharing practices.

Your task is to extract structured CANDIDATE KEY RESOURCES TABLE (KRT) dataset rows from the article.

Focus on datasets and data resources that could plausibly appear in a KRT.

## YOUR STAGE IN THE PIPELINE

This is the RECALL stage of a two-stage extraction. Your output is a candidate list, not
the final table: a second stage applies the KRT-eligibility gate (deposition identifier
required, assay readouts and derived values removed, cited-not-used entries dropped) and
decides what actually becomes a row.

So: your job is to find every candidate and GROUND it in an exact span. It is not your job
to predict what the eligibility gate will keep. What you must still exclude are things that
are not data at all (the "WHAT TO EXCLUDE" list below) — those cost the second stage work
without ever becoming rows.

---

## WHAT TO EXTRACT

Extract a DATASET_ROW ONLY if at least one of the following is true:

1. Clearly defined datasets:

* genetic datasets (RNA-seq, metagenomics, transcriptomics, read alignment, qRT-PCR, Sanger sequencing, genotype etc.)
* protein structures with PDB IDs
* proteomics, liquid chromatography followed by mass spectrometry (LC-MS/MS)
* datasets deposited in repositories (NCBI BioProject, SRA, GEO, Zenodo, PRIDE, MassIVE, EMDB, PDB, ProteomeXchange, BioImage Archive, figshare etc.)
* supplementary datasets explicitly described as data (Source Data, Extended Data etc.)
* patient clinical and human subject table data

2. Reused datasets:

* reference genomes used for alignment
* external datasets directly used as input data in the study (GP2, UK BioBank, GWAS, PPMI etc.)

3. Explicitly recorded experimental measurement datasets:

* cell counts, flow cytometry (FACS), fluorometry
* chromatography (HPLC, SEC etc.)
* densitometry
* assays (ELISA, BCA protein assay, Bradford, enzymatic assay etc.)
* fluorescence intensity, spectrometry, absorbance
* behavioral tasks (rotarod, open field etc.)
* mass spectrometry, lipidomics
* microscopy images (brightfield, confocal, immunofluorescence, immunohistochemistry, electron microscopy, 2-photon imaging etc.)
* electrophoresis images (Western blots, immunoblots, dot blots, SDS-PAGE etc.)
* Magnetic Resonance Imaging (MRI), CT
* fiber photometry
* videos, webcam recordings
* electrophysiology, whole-cell patch-clamp recordings, series resistance, current changes, amplitude
* Fast-scan cyclic voltammetry (FSCV), voltammetry
* quality control (mycoplasma contamination, RNA integrity, cell counts)
* ONLY if clearly described as acquired, collected or recorded data
* NOT if they are part of statistical analysis or derived metrics

### Instruments are EVIDENCE, never the row itself

A named instrument (Illumina / NextSeq, BD LSRFortessa, Axopatch or Axograph amplifiers,
Orbitrap, Opera Phenix, FLIR camera etc.) is evidence that data of the corresponding type
was RECORDED. Use it to decide that a dataset exists — then name the row for the DATA TYPE,
never for the instrument.

  "sequenced on a NextSeq 2000 (Illumina)"  → dataset_name "RNA-seq"     (NOT "NextSeq 2000")
  "recorded on a BD LSRFortessa"            → dataset_name "Flow cytometry" (NOT "LSRFortessa")

Do NOT emit a row for an instrument that is merely mentioned with no indication that data
from it was collected in this study.

### Recorded measurement vs. derived value

Some items below appear close to the "derived data" exclusion. The test is whether the
manuscript describes a MEASUREMENT BEING ACQUIRED, not a number being computed from one:

* densitometry of blots, read alignment output, cell counts → EXTRACT when the text
  describes them as measured/recorded/collected data that was retained.
* log2 fold-changes, normalized values, ratios, statistics computed FROM those measurements
  → DO NOT EXTRACT.

When a sentence describes both, extract the measurement and ignore the computation.

## WHAT TO EXCLUDE (VERY IMPORTANT)

DO NOT create DATASET_ROW for:

* biological entities (genes, proteins, taxa)
* lab materials (plasmids)
* statistical analyses (PCA, diversity metrics, correlations)
* derived or transformed data (log2 values, normalized values)
* plots, figures, tables or visualizations
* references to tables/figures without explicit dataset description
* software/tools (unless paired with dataset)
* vague mentions of "data" without clear dataset identity
* supplementary tables unless explicitly described as datasets

## STRICT RULES

* Extract one consolidated DATASET_ROW per unique dataset — except when the dataset
  has two distinct deposits (two repositories, or two different identifiers), which
  get one row each. See "Extraction unit" below.
* DATASET_ROW.extraction_text MUST be exact substring
* Supporting spans MUST be exact substrings
* Do NOT hallucinate identifiers or repositories
* Do NOT over-generalize without evidence
* If a dataset existed before this study (even if reprocessed or analyzed), classify it as REUSED
* If an accession, DOI or URL is present, `repository` MUST be the repository that
  identifier belongs to — not the wording used in the sentence. A row that says
  "This paper" alongside `EMD-57672` has repository "EMDB"; alongside `GSE328400`,
  "GEO"; alongside `10.5281/zenodo.X`, "Zenodo". Never invent a repository for an
  identifier you do not recognise — leave it empty instead.

### Extraction unit: ONE DATASET_ROW PER UNIQUE DATASET *DEPOSIT*

Emit **one consolidated DATASET_ROW per unique dataset**. When the same dataset is
described in several passages — e.g. a Methods sentence about the sequencing run AND
a KRT-style summary line for the same accession — that is still ONE row, not two.
Ground it in the span that carries the identifying details (repository, accession,
DOI or URL).

  "…sequenced on a NextSeq 2000…" + "Dataset | GEO | This paper | GSE328400…"
    → ONE row (repository GEO, accession GSE328400)

**The one exception:** when a dataset has **two genuinely distinct deposits** — two
repositories, or two different identifiers — emit **one row per deposit**. The
attribute fields are single-valued, so a single row cannot carry both, and
collapsing them would silently discard one identifier.

  "…zenodo.org/records/14270014 and phs004421.v1.p1…"
    → TWO rows: one (Zenodo, url=…14270014), one (dbGaP, accession=phs004421.v1.p1)

Duplicate spans of the same deposit: merge. Distinct deposits: keep both.

## THE EXAMPLES ARE NOT DATA

The worked examples you were shown demonstrate the OUTPUT FORMAT. They are not a checklist,
not a starting set, and not content you may extract. They come from other papers.

Never emit an item because it appeared in an example. If an example's dataset also genuinely
appears in THIS article, you extract it from this article's text and span — never by copying
the example.

An article with no depositable datasets is a normal and correct result. Returning an empty
list is always better than returning an item this article does not contain.

## FINAL RULE

Every item you extract MUST be grounded in an exact span of THIS article. If you cannot
point to the text it came from, it is not a finding and must not be emitted. This rule has
no exceptions and outranks every recall instruction above.

When in doubt about whether the item is DATA AT ALL (vs. a biological entity, a lab
material, an analysis, a figure, a tool, or a vague mention):
→ Do NOT extract the item.

Doubt about whether a genuine dataset — one that IS in this article — will survive KRT
eligibility is NOT your call: the second stage decides that. Extract it, grounded in its
span. That is the only doubt the second stage resolves for you.
